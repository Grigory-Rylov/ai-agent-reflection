# OMP vs Go Agent — Сравнение и идеи для улучшения

**Дата:** 2026-07-30
**Сравниваемые проекты:**
- **oh-my-pi (OMP)** — `~/projects/ts/oh-my-pi` (v18.0.11, MIT, Stencil Labs)
- **Go Agent** — `~/projects/go/ai-agent-reflection` (self-hosted VK bot + локальные LLM)

---

## 1. Что такое OMP

Терминальный кодинг-агент (форк Pi от Mario Zechner):
- **TS-ядро** (Bun ≥1.3.14) — LLM-клиент, агент-цикл, тулзы, сессии, TUI, MCP, extensions. 17 пакетов в monorepo.
- **Rust-нативный слой** (~80k LoC, 8 crates + brush-shell) — встроенный bash, grep, glob/fd, tree-sitter/ast-grep, PTY, gitoxide/jj, workspace isolation.
- 4 точки входа: TUI, one-shot CLI, SDK, RPC/ACP server.
- 60+ LLM-провайдеров, 31 built-in tool.
- Bazel + Cargo + Bun.

## 2. Что такое Go Agent

Self-hosted VK-бот + локальные LLM (llama-server):
- **Go** — один статический бинарник `agent` + `agent-restarter`.
- VK Bot API gateway → agent loop → tools (shell, file, web, MCP) → LLM.
- Мульти-агентный пайплайн: lead → worker → reviewer → qa (sub-agents).
- SQLite хранилище сессий, slot-based KV-cache (llama-server /slots).
- Permission-система: allow/deny/ask + runtime-learning.
- systemd-деплой, self-update через VK-команды.

## 3. Чем OMP лучше (идеи для Go Agent)

### 3.1 Контекст-менеджмент

| Механизм OMP | Текущее состояние Go Agent | Идея |
|---|---|---|
| **Спекулятивная асинхронная компакция** — стартует суммаризацию в «пред-пороговой» полосе (75–85% usable), результат кэшируется. При реальном overflow — мгновенное применение. | Компакция реактивная: `compactIfNeeded` (agent_impl.go:277) срабатывает только при `IsOverflow`. С медленной локальной LLM это блокирует ход на 30–120 сек. | **Speculative compaction**: при 75% usable запустить goroutine с LLM-суммаризацией. При overflow использовать готовый результат. |
| **Многометодная компакция**: (a) механическое вычуривание tool-результатов в ссылки на артефакты (без LLM), (b) handoff-документ, (c) LLM-суммаризация | `PruneMessages` (pruning.go) — механическое вычуривание. `CompactWithOpenCode` — LLM-суммаризация. Но нет «ссылок на артефакты» — обрезанный вывод просто заменяется `[Old tool result content cleared]`. | Сохранять обрезанный вывод в файл, в контекст класть ссылку `tool-output/xxx.txt`. Модель может перечитать по ссылке. |
| **Context promotion** — перед компакцией переключается на модель с большим контекстом | `models.json` уже имеет модели с разным контекстом (qwen3.6 262k, ninfer 150k), но маршрутизация по размеру контекста не реализована. | При подходе к overflow переключиться на модель с большим контекстом, а не делать компакцию. |

### 3.2 Безопасность

| Механизм OMP | Текущее состояние Go Agent | Идея |
|---|---|---|
| **TTSR** (Token-Time Stream Rules) — regex/ast-правила прерывают стрим в середине токена, инжектят system-reminder, продолжают с той же точки | `loop_detection.go` — детект зацикливания (3 одинаковых tool-вызова). Нет stream-level правил. | Stream-правила: «никогда не коммить без разрешения» — правило срабатывает прямо в стриме, без налога на контекст. |
| **Critical patterns** — `rm -rf`, `mkfs`, `dd if=` и т.п. принудительно требуют approval даже в yolo-режиме | `permission.go` — allow/deny/ask + runtime-learning. Но нет жёсткого списка «всегда ask» — пользователь может случайно allow-нуть `rm -rf /`. | **Critical patterns**: статический список опасных команд, которые ВСЕГДА требуют ask, независимо от permission-правил. |
| **Soft tool requirements** — цикл reminder→escalation, если модель не вызвала обязательный tool | Нет аналога. Модель может «забыть» использовать `question` или `send_file`. | Обязательные тулзы: если модель не вызвала `question` в N ходов — инжектить reminder. |

### 3.3 Мульти-модельность

| Механизм OMP | Текущее состояние Go Agent | Идея |
|---|---|---|
| **Роли моделей** (default/smol/vision/advisor/plan) — разные модели на разные задачи | Одна `default` модель на всех агентов. `models.json` поддерживает несколько моделей, но ролевая маршрутизация не реализована. | **Prewalk**: план на большой модели (262k) → исполнение на дешёвой (150k). Прямой выигрыш по скорости. |
| **Advisor/watchdog** — отдельная маленькая модель на своём контексте следит за каждым ходом | `reviewer` есть, но только в пайплайне кодинг-задач. Нет лёгкого критика на каждый ход. | Watchdog на малой модели: после каждого хода — быстрая проверка на галлюцинации/зацикливание. |

### 3.4 Суб-агенты

| Механизм OMP | Текущее состояние Go Agent | Идея |
|---|---|---|
| **Schema-validated yield** — суб-агент возвращает результат, валидируемый JSON-схемой (strict/permissive) | `SubAgentTool.Execute` (subagent_tool.go:129) возвращает свободный текст `response`. Родитель не может надёжно парсить результат. | **Schema-результаты**: суб-агент возвращает JSON `{status, summary, files_changed, next_steps}`. Родитель парсит и использует. |
| **Фоновые процессы** (hub) — автособирализация долгих команд (build/test) + readiness-regex + уведомление | `ShellExecuteTool` блокирует ход до завершения (timeout до 600 сек). Нет фоновых задач. | **Background shell**: `shell_background` стартует команду, `shell_check` проверяет статус. VK-уведомление при завершении. |

### 3.5 Сессии и память

| Механизм OMP | Текущее состояние Go Agent | Идея |
|---|---|---|
| **Rewind/ветвление** — сессии как дерево (JSONL, parentId), откат к любому сообщению | SQLite-сессии + `/clear`. Нет rewind. | Rewind: «вернись туда, где я ошибся» — откат к сообщению N и переответ. |
| **Память**: retain/recall + MEMORY.md (двухфазная LLM-экстракция) | `session memory` — базовое сохранение. Нет LLM-экстракции ключевых фактов. | MEMORY.md: после сессии LLM извлекает ключевые факты → MEMORY.md → подгружается в следующий раз. |

## 4. Чем Go Agent лучше (не надо перенимать)

- **Self-hosted + локальные LLM**: приватность, нулевая стоимость, нет зависимости от API. OMP заточен под облачные провайдеры.
- **VK-UX**: question-диалоги с клавиатурами, thinking в отдельный чат, отправка файлов, attachments (image/video→text). У OMP этого нет.
- **Restarter с /update /restart /b** — самообновление по команде из VK. Уникально.
- **Slot KV-cache** (llama-server /slots) — быстрый повторный prefill между ходами. У OMP не применимо.
- **Пермишены с runtime-learning** («Always allow») и per-agent политиками — ближе к реальности личного бота.
- **Простота**: один статический бинарник + systemd против Bun+Rust+Bazel.
